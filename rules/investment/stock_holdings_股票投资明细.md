# 模块规则：期末按公允价值占基金资产净值比例排序的股票投资明细

- `rule_id`: `investment.stock_holdings`
- `version`: 1
- `table_kind`: `detail`（重复证券行 + 披露排名字段）
- 公共契约：[`common_公共规则.md`](common_公共规则.md)

## selector

- 标题别名：`期末按公允价值占基金资产净值比例大小排序的股票投资明细`、`报告期末按公允价值占基金资产净值比例大小排序的股票投资明细`、`期末指数投资按公允价值占基金资产净值比例大小排序的所有股票投资明细`、`期末积极投资按公允价值占基金资产净值比例大小排序的所有股票投资明细`、`报告期末指数投资按公允价值占基金资产净值比例大小排序的前十名股票投资明细`、`报告期末积极投资按公允价值占基金资产净值比例大小排序的前五名股票投资明细`、`前十名股票投资明细`、`前十名股票投资组合`。
- 必需列角色：`stock_code`、`stock_name`、`quantity`、`fair_value`、`ratio_of_net_assets`。`rank` 可选；若有则抽取，但不作身份键。
- 父模块下的普通投资、积极投资等子表分别建表实例。

## scope

- 表实例由 `fund_id`、`period_end`、`investment_scope` 和表的披露范围共同确定；`market_scope` 是表内证券的市场上下文，不代替基金或投资范围。
- 招募说明书是本模块的核对对象，并定义需要核对的证券集合；定期报告是参考来源。先确认统计期和投资范围可比，再核对招书列出的证券。定期报告可以披露更大的集合（例如招书披露前十名、报告披露全量），这时只比较招书列出的证券，报告中其余证券不报差异，也不要求人工复核。
- 若招书要求全量，而定期报告只披露前 N 名，或报告的前 N 范围小于招书要求的范围，报告证据不足以覆盖目标集合，应保留待复核；不得据此断言招书项目在报告中缺失。
- 普通投资、积极投资等子表是不同表实例。不得跨子表合并同代码证券，也不得仅因基金相同就把不同范围的表互相比较。
- 使用稳定语义描述表级范围：`investment_scope` 为 `all`、`index`、`active`、`other` 或 `unknown`。明确针对该章节整体股票投资、没有拆分投资类别的表为 `all`；存在拆分时保留对应子表范围。
- `disclosure_scope` 为 `all`（全量）或 `top_n`（前 N 名），无法确认则为 `unknown`；`top_n` 还须填写原文 N 到 `limit`，不得把 N 固定为十。表级范围放入 scope，同一实例内每行沿用已确认的投资范围。

## row_policy

- 本模块是按披露指标排序的证券明细表。表格行序、`rank`、页码、跨页位置以及公允价值/比例的排序位置都会随报告变化，均不是证券身份，也不能用于两份文档之间的逐行配对。
- 招募说明书表内实际披露行构成本次比较的目标集合。按证券身份在定期报告中查找对应项；报告额外披露的证券不参与本次差异判断。同一证券即使排名、物理行号或所在页不同，也必须作为同一证券核对，不能因此判为单侧出现。
- 首选身份为可确认的 `market_scope + investment_scope + normalized_stock_code`。指数投资与积极投资中可能出现同一证券代码，不能因此合并。`investment_scope` 同义表达需归一到稳定语义键；`market_scope` 应按原文可证的市场上下文填写为统一值：`domestic`、`hk_connect`、`other` 或 `unknown`。不得根据排名、证券名称、数值，或代码外观自行推断市场；没有原文依据时填 `unknown`。
- 两侧市场信息均明确且一致时，按市场/交易所与规范代码匹配。若一侧或两侧市场信息缺失，只有当对应表实例及投资范围内该规范代码各自唯一，且没有其他相冲突的市场证据时，才可按代码匹配；否则标记 `UNRESOLVED_ROW_IDENTITY`，不可判为 `MISSING_ROW`。
- 相同代码在同一表实例重复出现时，不得静默去重或任选一行。先检查是否属于不同子表/投资范围；若仍在同一范围内重复或无法区分，标记 `UNRESOLVED_ROW_IDENTITY`。
- 股票名称是匹配后的交叉校验字段，不单独作为主键。代码相同但名称冲突时保留配对并报告冲突、要求复核；名称相同但代码不同，不自动配对。
- 必须抽取所有实际披露行，保留每行原始序号、证券代码、证券名称及字段证据。标题中的“前十名”限定预期披露范围，不补造未披露行。

## column_policy / bindings

| `column_key` | 语义 | `value_type` | 单位 |
|---|---|---|---|
| `rank` | 披露序号 | ordinal | 原文序号 |
| `stock_code` | 股票代码 | identifier | 保留原码并规范化 |
| `stock_name` | 股票名称 | text | 原文名称 |
| `quantity` | 持有数量 | quantity | 股或原文标注单位 |
| `fair_value` | 公允价值 | money | 元或原文标注单位 |
| `ratio_of_net_assets` | 占基金资产净值比例 | ratio | 百分数 |

证券身份由 `stock_code` 与可确认的市场信息构成。`rank` 是披露顺序属性，必须绑定到 `reported_ordinal` 并保留原始证据；它不可进入证券身份、不可作为配对条件，也不可单独形成持仓差异。`row_id` / `row_index` 仅用于定位当前文档中的证据，不能跨文档作为行身份。

## comparison

1. 先核对表实例、基金、统计期、投资范围以及报告披露范围是否足以覆盖招募说明书的目标集合。上下文不一致或不确定时，停止逐行缺失判断并标记不可比/待复核。
2. 以招募说明书中的全部目标证券为基准，在定期报告中按证券身份查找对应项；不反向把仅在定期报告中出现的证券列为差异。不得用相同行号、相同排名、相同数值或相同行序代替身份匹配。匹配结果应能解释每一行对应的证券及其原文证据。
3. 排名变化只作为披露顺序信息保留，不作为行缺失、证券身份变化或数值错误。先匹配证券，再逐项比较股票名称、数量、公允价值和净值比例；数量/金额/比例不同才报告相应字段差异。
4. 只有在两侧表实例及披露范围可比、表格行抽取完整、且某证券身份在一侧可确认而另一侧确实不存在时，才报 `MISSING_ROW`。身份信息缺失、重复、市场冲突、抽取不完整或配对无法确认时，报 `UNRESOLVED_ROW_IDENTITY` / `UNRESOLVED_STRUCTURE`，不能把不确定性写成单侧出现。
5. 每项已配对差异须指出证券代码/名称、具体字段、两侧原始值及各自页码/bbox。若字段一致而仅排名不同，不产生数值差异。
