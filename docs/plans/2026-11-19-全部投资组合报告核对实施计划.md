# 全部投资组合报告核对实施计划

日期 2026-11-19  
状态 实施方案，附注核对范围已确认

## 目标

以招募说明书中实际披露的“投资组合报告”为目标范围，从同一基金、同一组合报告期末、且在招募说明书披露时点可用的定期报告查找依据。对子模块逐项核对，允许同期间年报比招募说明书披露更多行或表。结果可跳到双方原文，指出实际差异和证据不足的具体原因。

## 现有基础和缺口

当前三项模块从投资组合规则目录自动注册。执行器可处理按规则声明的章节、列语义、行身份、范围和续表。新增规则未生成匹配的执行计划时，规则加载会失败。现有编辑接口以文件已存在为前提，首批新增规则需要使用受控的编译和启用步骤。现有模块比较也不能把所有可选模块的“双侧未定位”直接视为不适用，启用大量规则前应先处理这一状态。参见[规则加载器](../../app/rule_compiler.py#L109)、[规则保存](../../app/main.py#L331)、[模块比较器](../../app/comparison.py#L654)。

已有本地 Markdown 样本显示，易方达上证 50 年报按债券品种列示，纳斯达克 100 类样本有按信用等级列示和国家地区分布。区分国内、境外及不同投资范围需看章节和表头，章节号仅作提示。

## 建议覆盖清单

| 实施批次 | 模块 | 比较口径与风险 |
| --- | --- | --- |
| 首批 | 债券分类组合、前五名债券投资明细 | 分类表按品种或评级类别对齐。品种与评级两种口径分别识别，只有同口径才比较。明细优先用债券代码及市场范围定位，比较数量、公允价值、占净值比例等实际披露字段。排名变化按规则定义处理 |
| 第二批 | 资产支持证券、贵金属、权证、基金投资、国家或地区分布 | 分别声明表头、业务身份、市场维度、计量单位及比例分母。按原文确认是否适用。基金投资可含目标基金，按上下文区分 |
| 第三批 | 衍生品和其他投资组合专项表、股票重大变动（目标实际披露时） | 区分持仓、交易与评价。衍生品按合约及适用方向识别，期货和其他衍生品按披露口径各自比较。股票买入和卖出明细及汇总按其各自期间和字段处理 |
| 第四批 | 附注中的表格及文字 | 表格可包括其他资产构成、转股期可转债、流通受限证券。附注只核对双方均披露且原文可定位的事实，例如发行主体、事项、否定披露、适用范围或时间窗口 |

这是启动清单。实施前用招募说明书和各类型参考报告列章节覆盖清单。实际披露但未命中已启用规则的内容在验收留痕中列为“未覆盖”，按新增模块登记，作为从首批推进至“全部”的依据。使用章节树和规则覆盖关系，保留参考文档独有子章节供排查，避免将目录、表注或同节子标题反复计为未覆盖模块。

## 已确认的附注规则

- 仅纳入双方均披露、可定位，且主体、事项、期间与适用范围可以相互对应的事实。附注内的表格和值也按这一范围判断。
- 相同事实可以使用不同措辞和排版。双方证据明确且事实不一致时才列差异，保留两侧引文及坐标，例如同一主体、同一期间下的明确肯定与否定。
- 单侧补充说明、段落编排或字句变化不计差异。无法建立事实对应、缺少原文定位或提取截断时，记录具体证据缺口，不得推断另一侧有冲突，也不得将未覆盖内容算作已核对一致。
- 由 Markdown 声明事实身份、适用范围和比较方法，程序复用通用事实对齐及证据核验。

## 通用执行与状态

- **路由。** 先定位投资组合报告及实际子章节，再用规则称谓、标题语义、表头和段落上下文选定证据。续表作为同一逻辑表处理，坐标保留物理页。匹配粒度由规则明确为整节、表、业务行或段落事实。
- **可选模块。** 目标侧有数据或明确无持仓时进入对应模块判断。目标范围完整且经查证未披露的可选模块可排除。出现候选漏检、续表缺失或结构歧义时留待复核，不能以空集合认定无持仓或不适用。
- **对齐与结果。** 比较目标侧实际披露的行和字段。参考多行、额外表或额外披露是否纳入由规则声明。目标已披露但参考缺失时，只有完成相关范围覆盖后才判定缺少依据；模型漏提或上下文截断时保留待复核。双方明确同范围无持仓可以一致，保留双方原文。
- **通用证据。** 表格保存章节、行键、列语义、原文、页码、坐标和来源 ID。若文字附注需要新能力，新增通用段落事实比较，事实键、语义判定与复核条件由 Markdown 声明。遇到不支持的语义，说明原因并保留待复核。
- **规则发布。** 在隔离的规则目录中创建并编译 Markdown，检查名称、稳定 ID、列字段、期间、适用性、来源和证据约束。验证完整规则集可加载后再成批启用，记录版本。已有任务继续读取自己的规则快照。发布失败保留上一生效版本。

## 实施拆分与验收

1. **盘点样本。** 至少用债券、股票或 ETF、QDII 三类真实产品做章节映射。人工建立每种模块的源章节、匹配身份、口径和预期结果，标明文件、页码及跨页情况。
2. **首批落地。** 先跑通债券品种与债券明细。验证“只增加模块 Markdown 和编译计划即可识别新表”，如遇到通用能力缺口，明确是适用性、定位、续表还是单位。
3. **按批扩展。** 以真实样本覆盖同名异义、不同口径、跨页合计、无持仓、参考侧超集、目标侧必查项缺值，以及参考文件期间错误。验证原有三个模块输出无业务回归。
4. **附注验收。** 双方同义且可定位的事实判一致，双侧可举证的事实冲突列差异。单侧说明、纯措辞变化及事项范围不同不列差异。双方疑似对应但有一侧定位失败或正文截断时，保留证据缺口，既不报差异也不计一致。
5. **覆盖收口。** 交付模块覆盖清单、每模块生效规则版本、真实任务 ID 和原文页码。对尚未覆盖或没有语料验收的章节给出具体状态。

首批建议优先从已有招商产业债券型基金或博时信用债语料选取同期间的招募说明书和定期报告。先确认两份文档实际披露了对应数据，再作为有持仓样例。
