# 中文业务规则与内部执行契约

状态：运行时已接入通用执行计划协议 v2；本文按当前实现维护。概要规则加载、投资规则比较及计划校验均已读取 Markdown 编译出的执行计划。真实双流程任务尚未按主实施计划完成验收，不能据此认定整体改造已完成。

## 一、管理人员维护的规则正文

规则文件使用 Markdown 的普通中文标题和段落，不放 TOML、JSON、英文枚举、Excel 坐标或解析器表格。文件名及所属业务目录由系统维护，用作稳定身份，不作为业务判断条件。

任何业务规则的差异都不得靠 Python 中对稳定 ID、文件名、标题、标签的 `if/else` 实现。新增章节或指标应通过新增中文正文和生成新的执行计划完成；如果不能映射到通用能力，编译器要明确拒绝并解释缺少的能力。

投资组合模块样稿：

```markdown
# 报告期末基金资产组合情况

## 核对对象
以招募说明书中实际披露的资产组合项目作为核对范围。定期报告多披露的项目不单独列为差异。

## 查找内容
在两份文件各自的资产组合报告相关章节中查找完整表格内容，包括跨页续表、表注、父子项目和合计。

## 来源与适用范围
招募说明书是被核对文件，适用的定期报告是参考文件。先确认基金身份、报告期和投资组合范围相符。

## 比较方法
按项目含义及上下级关系对应；金额和比例分别比较。金额单位、比例分母和报告期要一致。

## 特殊披露
合计按原文单独比较，不用自行计算值代替。保留原文明确的未持有说明，以及横线、零值和空白的区别。

## 需要复核的情况
项目身份或父子关系不能确定、字段缺失、单位或比例分母不明、原文证据无法定位时，不判一致或差异，说明缺少什么证据。
```

概要管理费率样稿：

```markdown
# 管理费率

## 核对对象
核对产品资料概要披露的本基金管理费年费率。

## 查找内容
优先查看定期报告中基金管理费或管理人报酬相关披露；若报告确认未披露本项，再查看招募说明书中本基金管理费计提条款。

## 来源与适用范围
产品资料概要是被核对文件。定期报告是首选依据，招募说明书只在规则允许的补充情况下使用。确认基金身份、费率适用对象和费率生效期间。

## 比较方法
比较年费率百分比。管理费金额、计提基数和公式不是本项比较值。

## 特殊披露
如果存在费率调整，按披露的生效时间判断该费率是否适用于概要编制时点。

## 需要复核的情况
没有找到依据不等于已确认未披露；未检索完整、模型失败、引用无法核验或费率生效时间不明时，标记待复核，不能自动改用招募说明书。
```

## 二、系统生成的执行计划

保存时使用当前配置的模型，将规则正文和适用的公共规则编译为版本化 JSON。执行计划只允许描述既有工作流支持的通用能力，不包含可执行代码、自由表达式或文件操作。编译结果不能再编码为旧业务 Markdown/TOML 后交由旧逻辑优先消费。

当前顶层结构：

```json
{
  "protocol_version": 2,
  "rule_identity": "由系统登记并固定",
  "rule_scope": "investment | product_summary",
  "display_title": "中文标题",
  "business_group": "中文业务分组",
  "target_role": "prospectus | product_summary",
  "reference_roles": ["periodic_report", "prospectus"],
  "search_intent": {
    "target_description": "中文语义描述",
    "preferred_sections": ["基于规则正文推导的章节语义"],
    "preferred_sections_by_role": {"periodic_report": ["参考来源章节语义"]},
    "include_continuations": true
  },
  "source_selection": {
    "primary_role": "periodic_report",
    "fallbacks": [
      {"role": "prospectus", "when": [{"fact": "primary.status", "operator": "equals", "value": "not_found"}], "when_any": []}
    ]
  },
  "row_matching": {
    "identity_description": "规则声明的业务身份说明",
    "identity_fields": ["从模型抽取事实中选择的通用字段角色"],
    "scope_fields": ["需要保持一致的通用范围角色"],
    "target_population": "规则正文定义的目标侧范围语义",
    "reference_superset_allowed": true
  },
  "comparison": {
    "identity_description": "按中文语义描述",
    "scope_conditions": ["基金身份、期间、范围等需确认的条件"],
    "context_checks": [
      {"label": "报告期", "target_path": "document.document_info.period_end",
       "reference_path": "document.document_info.period_end", "operation": "matches_target", "required": true}
    ],
    "fields": [
      {"field": "declared_fact", "label": "中文字段名称", "operation": "decimal|identifier|date|text|semantic", "required": true}
    ]
  },
  "evidence_requirements": ["原文引用、页码及定位要求"],
  "review_conditions": ["不足以自动下结论的情况"]
}
```

`when` 表示一组条件需要同时成立，`when_any` 表示组与组之间满足任一组即可。模型只生成 schema 支持的执行计划；计划由 `app/rule_plan.py` 校验，规则版本由规则正文、公共规则及编译协议共同确定。上例仅用于说明结构，不能直接复制为一条业务规则。

执行计划的 schema 表达通用系统能力，不允许包含 `if rule_identity == ...` 这类按单个规则 ID 分支。跨页表格目录、坐标绑定、数值归一和引用验证由共享能力完成，不由 LLM 编译器定义新算法。

## 三、能力映射和失败策略

- 规则语义映射到当前双流程的目标、来源、检索意图、比较范围、证据和复核条件。
- 编译器的 JSON schema、受支持枚举和值约束只维护在系统代码中；这属于产品能力边界，不属于业务人员需维护的第二份业务规则。
- 规则正文表达不清、前后矛盾或要求系统不支持的能力时，编译失败并指出对应中文区域。不得猜测缺失要求或静默继承旧的业务参数。
- JSON schema 只定义通用运算能力和安全边界。不能按固定 `item_id`、`module_id`、文件名、章节名映射到不同算法；业务规则通过计划中的身份/范围/比较描述驱动统一执行器。
- 比较器不能保留 `asset_allocation`、`industry_stock_portfolio`、`stock_holdings` 等按模块 ID 分叉的业务判断。行键构造、范围隔离、目标侧集合及辅助展示字段来自规则计划，底层只运行通用集合匹配与字段比较流程。
- Excel 来源单元格、行号、旧 `value_type` / `period_policy` 等兼容元数据不得覆盖编译计划，也不得单独触发业务结论。
- 必须通过合成规则结构测试：临时增加一个新章节规则，不改业务 Python 即可加载并执行已支持的通用步骤；未支持能力则编译时明确失败。
- 规则文件内容哈希、公共规则哈希、编译协议版本、提示版本和模型标识共同构成编译缓存键。
- 编译与激活是原子操作：旧执行计划继续服务旧版本；新规则编译、schema 校验及冲突检查通过后才整体激活。任务启动时固定原文和执行计划快照。
- 模型服务不可用时规则仍可预览和编辑；保存不得报告已生效。恢复服务后显式重试。

## 四、当前迁移边界及剩余验收

运行时保留既有领域输出字段和接口。前端通过规则 API 维护中文分区正文，内部 JSON 只在服务端用于执行，不要求业务文件携带 TOML、固定行键表或参数枚举。

投资组合比较已改为按计划中的身份、范围、字段和目标侧范围执行通用集合匹配；概要来源选择及比较也按计划驱动。仍需完成并留证：旧兼容规则字段消费者审计、无独立业务规则分支的合成执行、多个产品真实任务、概要主来源及补充来源的真实路由、规则保存后刷新与历史任务版本隔离，以及异常计划编译失败时旧活动版本继续服务的检查。投资模块行数据仍保留实际抽取行、证据与坐标。
