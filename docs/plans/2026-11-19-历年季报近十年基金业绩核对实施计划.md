# 历年季报近十年基金业绩核对实施计划

日期 2026-11-19  
状态 实施方案，四季报“过去一年”的采用条件已确认

## 目标

输入一份招募说明书和同基金历年的多份第四季度报告。从招募说明书的“基金的业绩”章节提取按年份及份额列示的数据，从每份合格四季报提取对应年度事实。逐年核对净值增长率及业绩比较基准收益率，记录每年的参考文档和证据。允许先核对已提供且合格的年份，并清楚呈现未覆盖年份。

## 当前代码和实样

- 批量上传可扫描多个文件，但前端每组仅提交一个定期报告 ID，后端创建任务也只接收一个参考 PDF。现有流程把报告、归档及右侧 PDF 预览都建模为单份文件。参见[前端提交](../../frontend/src/components/BatchUploadPanel.vue#L384)、[创建任务](../../app/main.py#L659)、[报告识别节点](../../app/runtime.py#L531)、[归档](../../app/audit.py#L41)。
- 组合核对在批量提交时要求报告期末一致。因此历史业绩应有独立任务模式和来源条件。历史报告也不能作为现有组合流程的候补报告混用。
- 本地已有的易方达上证 50《2025 年第 4 季度报告》转换记录显示报告期末为 2025-12-31，业绩表含“过去三个月”和“过去一年”两行，“过去一年”的两列收益率为 16.60% 和 12.90%。单凭该行标签仍需确认所指区间。此处用于说明输入形态，不能据此宣称近十年已验收。可查本地转换产物 reader.md（哈希前缀 304555ac，第 120 行）。
- 单份年报的年度图可另作补证备选。当前图像转 Markdown 的证据接入在概要流程，若以后启用含图片的年报补证，历史业绩流程还要复用这条转换与定位能力。只做五年年报核对会改变本项交付范围。

## 比较口径

| 决策 | 建议口径 |
| --- | --- |
| 年份窗口 | 以招募说明书业绩数据的已核验截止日期为锚，取最近十个已经结束的自然年。报告披露还须符合规则约定的可用时点。锚点缺失或冲突应提示待复核 |
| 对齐身份 | 基金身份、份额类别、自然年度及实际收益区间共同确认。年度同时比较基金净值增长率和对应的业绩比较基准收益率，独立绑定原文 |
| 成立和份额首年 | 基金或份额尚未存续的年份为不适用。已有部分年度只有两侧实际起止日期一致时才可比较，明确显示实际区间 |
| 四季报取值 | 优先“年初至年末”或含明确日期的同区间数据。四季报“过去一年”可在基金、份额和完整自然年区间都有证据时采用。过去三个月、不同期末的滚动一年、累计成立以来数据不能代入。首版采用四季报，年报补证另行确认 |
| 缺年与重报 | 少传或来源不合格的年份分别提示。相同哈希去重；同年同份额有不同版本时按 Markdown 已声明且经确认的适用时点、修订优先级处理，证据冲突留待复核，保留文件信息 |
| 差异和覆盖 | 单年明确不一致时报告差异；其他年份仍给出独立状态。只有适用年份全部有可比结论且一致时才报整体一致。部分完成显示例如“已核对 7 / 应核对 10 年”，并列出缺年。待复核、不适用和确认差异分别计数 |

## “过去一年”的证据要求

- 核对同基金和同一份额，确认所用的是对应年度的第四季度报告，报告期末为该年 12 月 31 日，且收益率表或其可关联说明能确认“过去一年”覆盖当年 1 月 1 日至 12 月 31 日。保存报告期末、份额及收益率行的证据，并记录用于确认区间的证据或已声明的期间定义。
- 单凭“过去一年”标签、文件名或封面日期不能认定年度口径。区间无法确认、份额年中才生效或与招募说明书的年度区间不符时，不能按完整年度采用该行。成立或份额生效首年另按双方可证实的实际存续区间比较。
- 年份窗口、证据要求和允许采用的来源写入 Markdown。程序校验日期、份额和引用，并按确认后的区间对齐。证据未齐时标记该年份及份额待复核。

## 技术方案

1. **任务输入与预检。** 在招募说明书入口增加“历史业绩核对”模式，提交一个招募说明书文件和参考报告 ID 列表。复用识别与上传限制，按已核验身份、文档类型、报告期末及发布日期展示候选年份；文件名可辅助发现，实际选择需有文档证据。上传预览列出同年重复、非四季报、身份冲突和缺年。普通投资组合任务继续按一份参考报告提交。
2. **文档归档和标识。** 每份历史报告使用独立文档 ID，保存其角色、原始文件名、PDF 哈希、期末、证据位置和可预览标识。扩展任务结果层，兼容旧任务单报告字段；逐年引用文档 ID，避免同页码跨报告串证据。重试和任务复盘读取同一文档与规则快照。
3. **分文件提取与聚合。** 招募说明书先定位完整业绩章节并生成带份额和区间的事实表。参考报告逐份读取少量业绩章节及识别时必需的封面信息，复用统一的文本与表格目录。按文件内容和规则版本复用可核验证据，独立并发受控；某个年份失败时，保留其他年份的结果和失败原因。
4. **通过规则选择来源并比较。** 中文 Markdown 定义近十年窗口、季度选择、有效区间、份额、字段、来源优先级及缺失状态。编译侧将这些条件映射到已验证的执行能力；Python 根据声明过滤、汇总、对齐和核验，不使用基金名称、固定页码或指标 ID 决定取值。可确定的百分比由程序按声明比较。原文期间不确定时保留待复核。
5. **交互和追溯。** 详情用年份、份额、两列收益率及状态展示逐年结果。点击一行联动左侧招募说明书、右侧对应年度报告并定位双方原文。保留版本选择依据、逐年覆盖和完整任务状态。
6. **按阶段交付。** 先验证一份招募说明书加一份四季报可完成一个年度并定位；再打通 2–3 年、缺年、重复和跨文件切换；最后用同一产品的完整历史验收近十年规则。

## 验收数据和通过条件

- 先用现有一到数个四季报样本验证不同表头、区间表达及引用证据，再准备同一基金全套合格报告。当前语料需单独盘点年份和份额覆盖，多个基金各一份报告不能作为十年样本。
- 独立预期登记每个年份及份额的起止日期、两项百分比、参考文件及物理页。覆盖正常一致、已确认差异、缺年、首年部分区间、同年重复或版本冲突、错误基金、报告晚于可用时点及缺少份额。
- 专项验收四季报“过去一年”：同份额且完整自然年可核验时采用，保留两列收益率与区间证据。只有年末日期而区间无从证实时保留待复核。错份额、首年不足一年、期末非年末等样例不得按完整自然年通过。
- 完整样本应看到按预期对齐的全部适用年份；缺年样本显示究竟缺哪些文件或证据；点击跨年项目能打开正确 PDF。确认旧的单报告组合任务和历史详情仍可用。
- 交付记录需包含真实任务 ID、输入清单及哈希、规则快照与证据覆盖。当前阶段只记录设计与现有样本形态。
