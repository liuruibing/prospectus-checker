# 招募说明书基金业绩章节合并与验收交接

## 1. 交付目标

PDF 比较只提供两种任务类型。

| 任务类型 | 核对对象 | 结果页 |
| --- | --- | --- |
| 招募说明书核对 | 招募说明书与定期报告 | 同一任务展示投资组合报告的各核对模块，以及“基金业绩比较表”章节 |
| 产品资料概要核对 | 产品资料概要与定期报告，按现有规则可用招募说明书补充 | 沿用现有入口和结果页 |

需求第 4 项是招募说明书的投资组合报告。第 5 项是同一份招募说明书中“基金的业绩”下的基金业绩比较表，以定期报告中的同期间事实核对最近十年。第 5 项属于招募说明书核对里面的一个章节，复用同一个任务 ID、进度、结果页和 PDF 查看器。

本交接以用户最新确认的两种任务类型为准。之前的《招募说明书核对扩展总方案》和《历年季报近十年基金业绩核对实施计划》中的独立业绩模式、专项上传和专项验收路径以本文件替换。历史报告的证据判定口径仍由现行 Markdown 规则约定。

## 3. 实施顺序

### 3.1 收口创建入口和旧任务

1. 将招募说明书核对统一到现有常规入口 `POST /api/jobs`，对应 `InvestmentComparisonWorkflow`。常规上传、批量提交、直接调用工作流和重新核对均按两种正式任务处理。
2. 检查后端工作流注册、原 `POST /api/historical-performance/jobs` 和 `/v1/workflows/{workflow_id}/runs`。前端入口和后端创建能力中都移除独立逐年业绩任务。常规流程仍可调用可复用的业绩比较函数。
3. 已存专项任务保留原归档和 PDF 证据，明确标注是旧版业绩结果。旧专项只有一份定期报告时，重跑复用归档文件创建新的常规招募说明书任务。旧专项含多份报告时保留查看能力，提示用户从常规入口选择使用的报告。原任务及既有结果保持可追溯。
4. 交付优先使用现有上传交互。单份定期报告有可核验数据就先完成可覆盖年度；同一报告披露多个年度时逐年使用。确实缺少来源的年份如实展示。为核满十年而设计更多来源能力时，也应放在同一任务内，新增上传体验不属于本轮纠偏范围。

### 3.2 在同一任务执行第 4、5 项

1. 复用 `app/runtime.py` 的 `InvestmentComparisonWorkflow` 与 `_check_performance`。保留常规任务的组合模块，将业绩比较结果以现有模块结构追加到 `result.modules`，让 `Workbench.vue` 展示。一个章节异常应保留其他章节已得结果和各自证据。
2. 投资组合按 `rules/investment/` 的已启用规则执行。双方投资组合截止期间不同，显示规则给出的不适用或待复核，以及各自期末。相同期间按原规则正常比较。逐项核对招募说明书披露范围，报告独有的额外投资明细按既有规则处理。
3. 年度业绩由 `rules/historical_performance/annual_performance_逐年度业绩.md` 定义。近十年以招募说明书中核验过的业绩截止日为锚，在适用区间内按基金身份、份额和实际收益起止日期对齐，比较基金净值增长率和同期业绩比较基准收益率。年报披露早于招募说明书属于正常来源关系，日期条件按该章节规则执行。
4. 同一报告原文明确披露多个年度时，使用规则窗口内各个有证据的年度，不能只保留报告期末所在年份。“过去一年”需有足以确认完整自然年的原文或可关联期间证据，并确认份额覆盖该期间。过去三年、过去五年、成立以来累计业绩不能用来填补单年。报告与表格页码、基金名称以及收益率样例用于测试，不写进程序。
5. 展开这个章节能看到已比较的所有一致项和差异项，点击明细定位双方 PDF。用简短覆盖说明交代缺证据的年份和份额；确需人工处理的当期条目仍能查看。缺证据不能算一致，也不能算数值差异。规则决定章节、业务口径和适用条件，Python 执行通用操作和证据校验。
6. 本次同时检查第 4 项的位置和已有规则是否正常出现。完整投资组合覆盖情况需给出与招募说明书实际披露章节的清单。只看到现有五个模块并不能证明所有适用投资组合章节都已核对；缺规则、缺原文定位或已通过应分别记录。

### 3.3 修复 PDF 证据联动

- 在 `frontend/src/components/PdfViewer.vue` 支持归档 `task_id + document_role` 作为可渲染的文档身份。临时预览继续使用 `preview_id`。文档切换、图片缓存和滚动定位均以实际文档身份为准。
- 常规任务左、右分别取 `prospectus` 与 `periodic_report`。旧记录保留实际归档角色，例如 `historical_report_001`。没有命中右侧证据时可以展示已选报告，但不得复用上一条明细的高亮。
- 在浏览器逐条点击 A、C 两份额的一致项，确认画面显示正确 PDF、物理页码、收益率所在位置及状态颜色。确保右侧页图有可阅读的高度。接口返回 PNG 和页码值只能说明后端可供图，浏览器需确认画面实际渲染。

## 4. 验收用例

样本目录为 `assets/新增产品语料_2026-11-09/招商产业债券型证券投资基金/`。使用已经配置的项目 API，并记录实际模型和任务 ID。无需调整模型配置。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 两种入口 | 检查上传、任务列表筛选、工作流列表与旧专项创建接口 | 只提供招募说明书核对和产品资料概要核对。旧专项 POST 不创建任务，公开工作流接口也不能绕过 |
| 主验收，较早年报 | 从常规入口提交 `2026-03-20_招募说明书更新.pdf` 和 `2025-03-28_2024年年度报告.pdf` | 同一结果返回投资组合模块和业绩章节。组合显示 2025 年末与 2024 年末的期间原因。2024 年 A 类两列为 4.15% / 2.75%，C 类为 3.64% / 2.75%，两侧一致。缺覆盖年份在该章节注明 |
| 同期组合及四季报 | 同一招募说明书配 `2026-01-21_2025年第4季度报告.pdf` | 继续执行已启用的组合规则。2025 年 A 类预期值为 1.26% / 2.75%，C 类为 0.75% / 2.75%。引用“过去一年”前须验证份额与期间原文；证据不足时给具体待复核原因 |
| 范围、差异和证据 | 定向用例覆盖一份参考报告有多个年度、超出十年、同年不同份额、不同期间或同期间数值有差异 | 窗口内所有有证据的行参与比较。窗口外排除。范围不符时不配对。真正的数值差异保留双方定位。未覆盖年度显示范围说明 |
| 旧任务和 PDF | 打开 `GvBhOn296SKiMZyHjrjAUHkH` 并点击 2024 年 A、C 类，再用其归档输入重新核对 | A 类查看招募说明书 PDF 第 54 页与年报第 7 页，C 类查看左 55、右 8。重跑生成一个完整常规任务，可同时查看投资组合和基金业绩 |
| 产品概要回归 | 用同目录产品资料概要和配套报告验证现有入口，以及已有的招募说明书补充路径 | 仍是产品资料概要任务，返回该流程原有指标和 PDF 证据 |

真实验收从标准上传或标准 `POST /api/jobs` 开始，提交后读取 `GET /api/jobs/{job_id}` 与归档中的模块和证据，再打开对应任务详情。记录执行状态、模块清单、已完成和待复核的真实项目及对应证据页。只有真实任务和页面两边都对上，才记录端到端通过。若环境或模型出错，记录任务 ID、阶段和错误，并区分单测、构建、接口、浏览器各自的结果。
