## 建议阅读顺序

1. `当前Python系统设计与技术路线评审稿.md`：当前设计、数据流、两类任务、模型与程序边界、已知风险和评审问题。

3. `rules/`：投资组合与产品资料概要的核对规则。
4. `evaluation/`、`scripts/`、`tests/`：多产品案例、预期结果、评测脚本和自动化测试。
5. 两份实施计划：用于对照现状和目标路线。

## 目录内容

- `app/`：全部 Python 应用模块。
- `rules/`：当前投资组合和产品资料概要规则。
- `tests/`：Python 测试源码，不含缓存与字节码。

## 请 Claude 评审时注意

请基于包内源码区分“已经实现”“实施计划目标”和“仍需实验验证”；优先指出架构风险、证据链/来源选择问题、跨页表格处理限制、工作流拆分和可量化验证方案。不要假设预期 JSON 已全部人工核验，也不要把自动化测试通过等同于多产品准确率已达标。
