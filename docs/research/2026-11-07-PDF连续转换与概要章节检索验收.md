日期：2026-11-07。分支：`11-06`。保留既有工作树；没有提交、推送、部署、修改原始 PDF 或切换模型配置。

## 本次改动

### 先恢复文档结构，再生成 Markdown

入口为 `app/pdf_document.py`、`app/pdf_markdown.py`。沿用参考项目“保留逐页事实，在文档级关联”的思路，不再把逐页转换结果直接拼接后交给模型。

- 从原生文字、线条及单元格坐标恢复表格；`lines_strict` 避免灰底矩形制造假列。仅有横线的表单另行恢复隐含列及合并单元格。
- 相邻页的末表、首表结合页边位置、列边界和章节边界归组；整表关联与半行续接分开处理。合计、净额继续保留为原表中的行。
- 缺少顶边的续页首行利用实际竖线恢复；表外残行只有在列归属得到支持时接回原表。
- Markdown 内嵌 HTML 表格，保留 `rowspan`、`colspan`。保留物理页、原字符、原始分页表、单元格、合并操作及图形资产，不只保存最终文字。
- 按输入与转换实现指纹缓存，使用文件哈希检查归档，避免复用旧版或已损坏的转换结果。
- 检查文字丢失、重复、变更和网格重叠。扫描件或续表归属有疑问时返回 `REQUIRES_REVIEW`，不静默降级为纯文本进入模型。

投资组合和概要流程均已接入此转换入口，仍保留原有可定位的证据 ID。文字守恒只能证明转换没有丢掉已提取字符，不能独立证明业务语义及所有行列关联都正确。

### 概要按章节找指标，减少重复上下文

入口为 `app/summary_check.py`。业务规则继续采用 Markdown，指标使用稳定 ID。

- 16 份规则增加按文档角色配置的章节提示。先检查指定章节；未命中时，通过仅含标题、页码、来源数量的目录选择其他章节。
- 按完整逻辑单元打包。命中跨页表的任一片段时提供整表；整表超预算明确记录未检查，不截断表体、不把未检查解释成未披露。
- 同批指标共享原文和逻辑表，只分别维护允许引用的 ID；删去重复的行、单元格及邻近内容载荷。
- 单包 16,000 序列化字符，同批数据 48,000 字符，系统与用户输入合计不超过 64,000 字符。这些是字符预算，不是精确 token 数。
- 已验证的目标事实及主来源事实锁定复用；仅对失败侧做局部恢复。主报告未确认缺失时，不擅自换用招募说明书。
- 修正数字小节层级：表格中的“1、决策依据……”不再结束“二、基金投资与净值表现”，续页的基准及风险收益特征可以继续按原章节召回。
