# 跨页表格成熟实现对照

核查日期：2026-11-06。仅查官方源码、官方文档及官方仓库 issue；未安装依赖、启动模型或运行这两套解析器。本文用于指导现有 PDF→Markdown 转换器，不代表对样例的模型效果实测。

## 结论

成熟实现把“相邻页是否为同表”“是否重复表头”“边界两行是否属于同一逻辑单元格”分开处理。PaddleX 的所查实现只做前两项和整行追加；MinerU 另外具备逐视觉列的 `cell_merge`。两者都依赖前序识别产出的表格结构，不能据此保证修复已经漏在表外的首行或错误列网格。[M2] [P1]

当前案例应先保证每页表格完整、列网格正确，再做跨页关系与单元格续接。已验证的 `lines_strict` 和根据实际竖线恢复缺上边框首行，应继续作为局部提取层的修复；无需为了借鉴跨页规则立即引入整套模型服务。此条是适配建议，不是这两套上游的功能承诺。

## 两套实现如何处理结构

| 关注点 | MinerU：规则快照 M2 | PaddleX：v3.7.2 P1 |
| --- | --- | --- |
| 候选表 | 必须显式 `page_idx` 连续；从上一页尾、下一页首找表，跳过页眉、页脚等白名单噪声；其他语义块阻断。 | 对传入列表中的相邻页，取上一页最后一个表、下一页第一个表；表前后仅允许限定标签或“续”等标记。合并函数本身不校验原始页号连续。 |
| 同表门槛 | 表宽相对差小于 10%；考虑表注、续表标题；总逻辑列数相同，或边界数据行结构兼容。 | 表宽相对差小于 10%；总逻辑列数相同，或上一页末行与下一页首个数据行的列数/显式单元格数相同。**不要求表头文本相同才合并。** |
| 列数 | 扫描 `rowspan` 占位与 `colspan`，区分有效列、显式列和渲染段；总列不同时仍可能按边界行通过，并有有限 `colspan` 调整。 | 扫描 `rowspan`、`colspan` 得到总列；边界行另比较 `colspan` 总和或 `<td>/<th>` 数量。不会把错误的 7 列自动理解为正确的 5 列。 |
| 表头去重 | 最多比较前 5 行；先比规范化文本、`colspan/rowspan` 与有效列，再以文本和渲染段一致作降级；跳过范围按表头 `rowspan` 扩展。 | 最多比较前 5 行；规范化全角与空白后，要求文本及 `colspan` 相同。这里不比较 `rowspan`，也没有前述表头跨行扩展。 |
| 被分页截断的单元格 | `cell_merge` 按视觉列映射，将下一页第一数据行指定单元格追加到前页末行；仅清空实际转移成功的源格；源行无语义内容时才删除，并处理 `rowspan`。 | `perform_table_merge()` 跳过重复表头后逐 `<tr>` 追加；**没有逐单元格文本续接**。它能合并表，不能据此声称已经合并跨页半行。 |

对应源码：MinerU 的候选/连续页检查在 [M2 尾部 1246–1311 行][M2-boundary]，列与表头/同表判断在 [M2 613–804 行][M2-structure]，单元格续接在 [M2 984–1070 行][M2-cell]；PaddleX 的全部规则在 [P1][P1]。P1 文件注明其合并逻辑借鉴 MinerU，因此不宜把两者视为完全独立的算法交叉验证。

## 模型与 API 的实际边界

**MinerU**：M2 的 HTML/坐标/标记合并代码本身是确定性后处理，`cell_merge` 是消费的输入元数据，不能据此推断每种后端都会自动正确生成它。当前 HEAD 另有已经落地的可选 LLM 后处理：只对规则已确认的续表，提取边界数据行的对应渲染单元格；数量不同则跳过；要求模型返回等长 0/1 数组，校验后按 `colspan` 展开到视觉列。官方配置中此功能默认关闭，启用需外部 OpenAI 兼容服务的模型、地址与密钥。它不是先用 LLM 任意判断整份文件，也没有承诺能从表外找回漏行。[M5] [M6]

**PaddleX / PaddleOCR-VL**：上游布局和表格内容由模型预测；所查跨页合并函数本身没有再次调用模型。实际入口是 PaddleOCR-VL 产线的 `restructure_pages(res_list, merge_tables=True, relevel_titles=..., concatenate_pages=...)`，内部明确调用 P1。对本任务应关闭不需要的标题重建，保持 `concatenate_pages=False`。官方文档已介绍此 API，属于已实现能力。[P2] [P4]

**不要混淆 API**：同一版本 PP-StructureV3 的 `concatenate_markdown_pages()` 只根据段落延续标记连接 Markdown 字符串，不能等同于上述跨页表格结构合并 API。[P5]

## 来源、JSON 与限制

MinerU M2 的 `merge_table()` 只在后页表格写 `continues_prev=True`；`merge_table_content()` 深拷贝输入后返回合并内容，保留前表外层信息。这样可以保留按页事实、把跨页拼接放到导出层；但合并后的单个 HTML 本身不提供每个字符的原始单元格坐标。当前输出文档也明确保留 `page_idx`、块、页面几何与生产者版本，适合保存结构化结果，不能只留 Markdown。[M2] [M7]

PaddleX P1 会把前表内容改为合并 HTML、清空后表内容，并用 `global_group_id` 指向前表。P3 的 JSON 序列化保留页号、块 bbox、`global_block_id/global_group_id`；这能表达块级归组，但不等于保留了每个合并单元格的来源。应在调用前另存未经合并的分页 JSON，避免原文只剩合并后的前页表体。[P1] [P2] [P3]

可从源码直接推出的限制：两套规则都可能误合并宽度/列数相同的相邻独立表；重复表头只是前缀行比较，重复数据行也可能被当作表头；前序表体漏字、错列、表外文字均不会由整行拼接可靠修复。PaddleX 的传入页面顺序与文件边界须由调用者保证，且缺少半行续接逻辑；MinerU 的视觉列续接仍依赖正确的列映射和标记。以上是代码推断，不是本次效果实测。

官方仓库的用户报告进一步说明不能承诺 100%：[MinerU #5345][I1] 的嵌套表跨页问题截至核查日以 `not_planned` 关闭；[#5417][I2] 曾报告边界丢左列和相邻行误合并，目前已以 `completed` 关闭。后者是历史失败样例，不能据此宣称最新版仍然复现，也不能仅凭关闭状态推断本项目样例已解决。issue 和机器人回复均不作为算法已修复的证据。

## 对当前转换器的最小适配建议

1. **保留逐页事实再导出**：保存原表、原始文字片段、页号/bbox/单元格来源；另记跨页归组、去重表头、单元格续接等操作。Markdown 是派生物，合并失败时仍可回到原页核对。
2. **先修提取，再分层决策**：沿用已验证的 5 列恢复与缺上边框首行恢复；先确认同表，再去重复表头，最后单独判断半行续接。净额/合计类末行不能仅因文字不同而排除在同表之外。
3. **借鉴约束，不照搬宽松判据**：页号连续、表宽/列边界相容、语义块不能跨越、表注/续表标题是有用条件；“列数一样就合并”不足以保护独立表。半行只有部分列续接时，应保留逐列决策，避免整行一刀切。
4. **最小验证集以完整性为主**：覆盖本次 5/7 列、缺上边框残行、独立相邻表拒绝合并、重复表头、多页链、混合单元格续接、合计末行；检查原文片段没有丢失/重复，数值没有跨行串联，来源可以定位。疑似关系保留原结构并记录原因，不能把猜测当恢复成功。
