# 概要章节路由与上下文预算

日期：2026-11-06。范围仅为产品资料概要的章节召回、上下文计划和证据恢复；未调用真实模型、未修改模型配置。

## 行为与接口

- 16 份规则 Markdown 增加 `section_hints_by_role`，按概要、定期报告、招募说明书分别维护通用章名；不在 Python 中写基金名称、具体值或章节编号。旧的共享 `section_hints` 仍可用于没有按角色配置的规则。
- 优先按章节标题/路径选完整章节。若标题提示未命中，才用字段词定位章节或整页。概要侧还要求存在字段标签候选，避免把同章所有未出现的指标都发给模型。
- `_chapter_directory()` 保留本地 `source_ids`。给模型的路由目录只有标题、页码、来源数量，不发送正文摘录；目录过长会分包。未命中项通过目录选择其他章节，随后一章一章检查。
- `reader_context.logical_units` 接受 `{unit_id,kind,pages,source_ids,markdown}`。命中跨页表的任何已绑定来源时，纳入整张表；保留原始 ID 和阅读顺序，不按物理页裁表。HTML table 与管道 Markdown table 均可作为结构提示。
- 单个完整逻辑表超预算时记录 `LOGICAL_UNIT_EXCEEDS_BUDGET`，不把其原文拆进恢复包；来源 ID 绑定不全时记录 `LOGICAL_UNIT_SOURCE_IDS_UNBOUND`。缺少逻辑表目录时仅能按已知原文行分包，不能据此声称恢复了完整表结构。
- 每个上下文包最多 16,000 序列化字符；每批指标载荷最多 48,000 字符；调用模型前再检查 system+user 不超过 64,000 字符。预算是字符数，不是精确 token 数。正文不截字符串，超预算单元有明确未检查记录。
- 同一批指标使用 `context_pool` 共享原文、逻辑单元与表格内容，每项只保留允许读取/引用的 ID 范围；相同完整表不会在同一请求里按指标重复序列化。内部证据候选与发送格式分离，仍逐项检查引用范围。
- 初始提取、引用恢复、章节扩展和招募补充都分批。找到并验证事实后停止该侧继续发送；`verified_target` 在后续引用恢复、章节查找和补充来源中锁定，代码拒绝模型改写。已验证主来源也可以锁定。
- 单包未命中只能表示当前范围未找到。程序仅在所选相关章节全部分包完成、没有超限单元、没有调用失败且每包明确未披露时确认该范围缺失；漏项、引用错误和未覆盖均保留 `UNRESOLVED`。这不等于已扫描全文所有章节。
- `context_coverage` 及 `primary_lookup.routing` 记录计划包数、已发送来源数、未检查单元和章节覆盖；模型调用继续记录实际 prompt 字符与耗时。完整来源内容仍留在 catalogue，不复制到每项 prompt 的邻近结构提示中。
- `build_document_source_catalogue()` 已使用主转换层 `verified_conversion()` + `bind_catalogue()`；主要和补充角色共用该入口。非 READY 转换抛出明确错误，不再静默回退 AnyDoc 或纯文本。

## 验证与剩余限制

受影响测试覆盖：预设章节优先于其他章节中的同词；目录来源 ID；完整 HTML 表；跨页逻辑表扩展；整表超预算与来源绑定缺失；长章不丢字分包；逐章扩展；不改写已验证目标；超预算调用前拒绝；转换未通过不回退；真实语料证据页和基金经理续页。

命令：`.venv/bin/pytest -q tests/test_summary_check.py tests/test_summary_rules.py tests/test_summary_routing.py tests/test_summary_job_pairing.py`。实际执行结果见本次交付说明；这里不将离线测试替身解释为真实模型性能证据。

剩余限制：字符预算尚未按具体模型 tokenizer 计数；目录未提供合适章节或单表超预算时保持未确认；章节识别仍可能受 PDF 标题碎片与目录样式影响；没有验证真实模型的语义召回率或耗时。新的原生转换器仍在主任务中调整，本次没有把无框概要未识别的表格宣称为已恢复；最终组合需在固定转换版本后复测。
